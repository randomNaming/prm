# 宝塔面板部署教程（本地构建 + 手动上传 + 反向代理 + HTTPS）

> 发布方式是**手动**：本地构建 → 把 `.output` 传到服务器 → 重启进程。
> 服务器只运行构建产物，**不构建、不装 bun、不需要 node_modules**，
> 也不需要对任何外部机器开放 SSH。

---

## 0. 为什么是「本地构建」

原先设想的是服务器定时 `git pull` + 自己构建（titleforge 那套）。实测在 `47.107.132.167`
上 `bun run build` 会在 element-plus transform 阶段被 OOM 杀掉，即使停掉 MySQL 容器腾出
1GB 依然如此 —— 这台机器的内存撑不起 Nuxt/Vite 构建。

所以构建挪到本地：本地跑 `bun run build`，把 `.output` 传到服务器，服务器只做一件事
—— 重启进程。副产品是服务器上不再需要 bun、不需要 node_modules，
装 bun 时踩的 GitHub 下载超时也一并绕过了。

## 1. 前置条件

- 云服务器 `47.107.132.167`，已装宝塔面板，MySQL 容器跑在 `3308` 且处于运行状态，库 `prm` 已灌好数据。
- 已有域名，A 记录指向服务器。
- 服务器已装 Node 20+（仅运行时用，构建不需要）。
- 本地仓库在 `main`，远程是 GitHub 的 `randomNaming/prm`。
- 走 4.2 一条命令版时才需要本地能免密 SSH 到服务器；4.1 手工上传不需要。

> ⚠️ **上线前必须知道的现状**：这个系统**没有任何认证**，22 个接口全部裸奔，
> 库里有客户姓名、电话、完整聊天原文。挂域名等于把它们放到公网上。
> 部署可以照做，但正式对外前至少要加一层访问控制（Basic Auth 或先只在内网/VPN 访问）。
> 详见 `docs/mobile-access-and-transport-security.md`。

## 2. 分支与推送

```
main ← 发布分支
dev  ← 日常开发
```

```bash
git switch main && git merge --no-ff dev
git push origin main
```

代码推上去之后，再按第 4 节把构建产物换到服务器。

## 3. 服务器初始化（一次性）

### 3.1 克隆仓库

```bash
cd /www/wwwroot
git clone -b main https://github.com/randomNaming/prm.git prm
cd prm
```

> 服务器上的仓库只是留一份代码备查（脚本、迁移 SQL）。**不需要** `bun install`，
> 也不需要构建；运行时只认手动上传的 `.output`。

### 3.2 swap（如果还没有）

swap 是机器级的，整台机器共用一份；已经加过就跳过。

```bash
free -m | grep -i swap        # Swap 行不是 0 0 0 就说明已经有了
```

没有再加，构建虽然挪到本地了，但 Node 运行时和 MySQL 挤在一起时仍可能需要：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 3.3 Node 20+

宝塔「软件商店 → Node.js 版本管理器」装 20.x，记下路径（一般是 `/www/server/nodejs/v20.x.x/bin`）。运行时只需要它，不需要 bun。

```bash
node -v            # 必须 ≥ 20
```

### 3.4 写 `.env`（唯一需要手工创建的文件）

`.env` 被 `.gitignore` 排除，上传和替换 `.output` 都不会碰它；它只存在于服务器上，别放进 zip。

```bash
vi /www/wwwroot/prm/.env
chmod 600 /www/wwwroot/prm/.env
```

```dotenv
# 服务器是正式库，用应用账号（无 DDL 权限），不要用 prm_migrate
DATABASE_URL=mysql://prm_app:密码@127.0.0.1:3308/prm

# 按需填写；不填则智能体对话停用，其余功能正常
ZAI_API_KEY=...
ZAI_BASE_URL=https://open.bigmodel.cn/api/coding/paas/v4
ZAI_MODEL=glm-5.3-flash

HOST=127.0.0.1
PORT=3100
```

> `HOST=127.0.0.1` 是故意的：外网只经 nginx 反代进来，应用端口不直接暴露。

### 3.5 systemd 常驻

```bash
cat > /etc/systemd/system/prm.service <<'EOF'
[Unit]
Description=crm-mini (prm)
After=network.target

[Service]
Type=simple
WorkingDirectory=/www/wwwroot/prm
ExecStart=/www/server/nodejs/v20.x.x/bin/node /www/wwwroot/prm/.output/server/index.mjs
EnvironmentFile=/www/wwwroot/prm/.env
Restart=always
RestartSec=5
User=www
Group=www

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable prm      # 只设开机自启，先不启动
```

> 服务器上此时还没有 `.output`，直接 `start` 会失败。等第 4 节把产物传上去，
> `systemctl restart prm` 会一并启动。

> `ExecStart` 里构建产物的绝对路径必须写全，`PATH` 在 systemd 环境里不可靠。
>
> **路线提醒**：宝塔「Node 项目管理器」也能托管，但它不归 `systemctl` 管，
> 第 4 节里的 `systemctl restart prm` 就重启不到新代码。统一走 systemd，别混用。

## 4. 发布（每次）

发布 = **把本地构建好的 `.output` 换到服务器上，然后重启进程**。只有这两件事。

### 4.1 手工上传（默认方式，不需要 SSH、不需要脚本）

1. 本地构建：

   ```bash
   bun run build
   ```

2. 本地打包，把 `.output` 压成一个 zip（Windows 右键压缩，或）：

   ```powershell
   Compress-Archive -Path .output -DestinationPath output.zip -Force
   ```

3. 宝塔 → **文件** → 进入 `/www/wwwroot/prm/`：

   - 先把旧 `.output` **改名**为 `.output.old`（留着回滚，确认没问题再删）
   - 上传 `output.zip`，右键解压，确认解压出的是 `.output/` 目录

4. 重启服务（宝塔面板 → 终端，就是服务器本机的 shell，不是外部 SSH）：

   ```bash
   systemctl restart prm
   ```

5. 验证：`curl -I http://127.0.0.1:3100/` 返回 200，再打开页面看一眼。

**回滚**：把 `.output.old` 改回 `.output`，`systemctl restart prm`。

> 为什么要先改名而不是直接覆盖：Linux 允许删除正在运行的文件，进程仍持有旧文件句柄，
> 所以"先删再传"不会影响正在跑的服务，重启前旧版本一直可用。

### 4.2 一条命令版（可选）

不想每次手动拖文件，就在本地仓库根目录执行：

```bash
bun run deploy
```

脚本（[push.mjs](../scripts/deploy/push.mjs)）做的还是上面 5 步，只是自动化了：

1. 检查 SSH 连通、本地 HEAD 与 `origin/main` 一致；
2. 本地 `bun run build`；
3. 打包 → `scp` 到服务器 → 服务器 `git reset --hard <commit>` 并整目录替换 `.output`；
4. `systemctl restart prm`，30 秒内轮询健康检查；
5. 比对迁移账本，**只报告**未应用的迁移，不动表结构。

主机地址默认从 `.env.db.local` 的 `SERVER_PROD_URL` 里取，也可显式指定：

```bash
node scripts/deploy/push.mjs --host 1.2.3.4 --user root
```

> 它需要你本机能免密 SSH 到服务器；如果不想开这个口子，就用 4.1 的宝塔文件管理器。

## 5. 反向代理 + HTTPS

宝塔面板 → **网站 → 添加站点**：域名 `crm.example.com`，PHP 版本纯静态。

### 5.1 证书

站点 → SSL → Let's Encrypt → 申请 → 开启「强制 HTTPS」。

### 5.2 反向代理

| 项 | 值 |
|---|---|
| 代理名称 | prm |
| 目标 URL | `http://127.0.0.1:3100` |
| 发送域名 | `$host` |

### 5.3 配置文件里必须核对的三处

```nginx
client_max_body_size 32m;          # ① 聊天记录粘贴可能很长

location / {
    proxy_pass http://127.0.0.1:3100;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # ② 流式回答（SSE）必须关缓冲，否则会攒到最后一次性吐出
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 600s;       # ③ 智能体长任务，别用默认 60s
    proxy_send_timeout 600s;
}
```

保存后 `nginx -t && systemctl reload nginx`（宝塔界面保存会自动重载）。

## 6. 防火墙

- 宝塔「安全」与云厂商安全组：只放行 `80/443` 与 SSH 端口。
- **`3100` 不对公网放行**，反代已覆盖。
- `3308`（MySQL）同理，只允许本机或跳板机。

## 7. 验证清单

| 检查 | 命令/操作 | 预期 |
|---|---|---|
| 服务活着 | 服务器上 `curl -I http://127.0.0.1:3100/` | `200` |
| 域名可用 | 浏览器打开 `https://crm.example.com/` | 正常加载 |
| HTTPS 强制 | 打开 `http://crm.example.com/` | 跳转 https |
| 流式输出 | 发一条智能体对话 | 逐字出现 |
| 一次完整发布 | 按 4.1 上传 `.output` 并重启 | 页面是新版本 |
| 结构一致 | 先设 `DATABASE_URL` 指向正式库，再 `node scripts/migrate.mjs --check` | 「结构已同步」 |

## 8. 迁移为什么不跟着部署走

你的硬约束是「正式库绝不能被本地代码改结构」。如果部署脚本自动跑迁移，
就等于把这条约束交给一次 push 决定。

| 动作 | 谁触发 | 怎么执行 |
|---|---|---|
| 改代码 | 你 | 本地构建 → 上传 `.output` → 重启（第 4 节） |
| 改表结构 | **你，且必须单独一次** | 先备份，再单独跑迁移（下面） |

标准上线顺序：

```bash
# 1. 本地在 prm_test 上写迁移、跑通
node scripts/migrate.mjs
# 2. 推送代码，并替换服务器上的 .output（第 4 节）
# 3. 确认正式库已备份后，本地直连正式库执行迁移
```

第 3 步在 PowerShell 里这样写（连接串取自 `.env.db.local` 的 `SERVER_PROD_URL`）：

```powershell
$env:DATABASE_URL = "mysql://prm_migrate:密码@47.107.132.167:3308/prm"
node scripts/migrate.mjs --confirm-prod
Remove-Item Env:\DATABASE_URL
```

不改 `$env:DATABASE_URL` 而直接跑，迁移会作用在 `.env` 里指向的 `prm_test` 上 —— 那正是测试库，不会误伤正式库。

另外正式库的迁移账号没有 `DROP` 权限，`TRUNCATE` / `DROP TABLE` 到库里也执行不了。

## 9. 常见坑

| 症状 | 原因 | 处理 |
|---|---|---|
| 上传后页面 404 / 白屏 | zip 解压后多套了一层目录，或 `.output` 名不对 | 确认 `/www/wwwroot/prm/.output/server/index.mjs` 这个文件存在 |
| 上传后还是旧版本 | 忘了 `systemctl restart prm` | 重启后再刷新 |
| `SSH 连不上`（仅 4.2 一条命令版） | 公钥没装上，或安全组没放行 SSH | 先手动 `ssh root@IP echo ok` 验证 |
| `本地 HEAD 与 origin/main 不一致`（仅 4.2） | 改了代码没推 | 先 `git push origin main` |
| 部署成功但页面还是旧的 | 服务器跑的是宝塔 Node 项目管理器，不归 systemctl 管 | 统一走 systemd |
| 页面 502 | `.env` 的 `PORT` 与反代目标不一致 | 两边改成同一个端口 |
| 对话不逐字出现 | 反代开了缓冲 | 5.3 的 ② |
| 长任务中途断开 | 反代读超时 60s | 5.3 的 ③ |
| 页面报 `Unknown column` | 代码更新了，迁移没执行 | 第 8 节，本地连正式库单独跑迁移 |
| 服务器 `git clone` 失败 | 网络到 GitHub 不通 | 换成已下载的源码包上传，或改用宝塔「远程下载」 |
